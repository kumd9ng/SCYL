# MEOW · SCYL 공통 계정

SCYL은 같은 Supabase Auth 프로젝트를 연결해 MEOW의 기존 회원 ID를 재사용합니다. 별도의 회원 복사나 이메일 문자열을 이용한 임의 계정 병합을 하지 않습니다. 음악 파일·분석·재생목록을 MEOW 서버로 전송하지 않습니다.

## 설정과 실행

`.env.example`을 로컬 `.env.local`로 복사한 뒤 같은 프로젝트의 `SCYL_SUPABASE_URL`과 공개용 `SCYL_SUPABASE_ANON_KEY`만 설정합니다. 관리자 `service_role` 또는 secret 키는 허용하지 않습니다. 설정은 브라우저용 공개 클라이언트 값으로 번들에 포함됩니다. `npm start`는 빌드한 웹 앱을 실행하고, `npm run native:sync`는 같은 인증 코드를 두 설치형 앱에 포함합니다. 설정이 없는 로컬 빌드는 계정 연결 없이 실행됩니다. 배포용 빌드의 설정 누락은 별도로 점검해야 합니다.

공식 저장소의 네이티브 빌드는 같은 이름의 GitHub 저장소 변수를 사용합니다. 다른 운영 서버로 배포할 때 `lib/account-links.mjs`의 `ACCOUNT_CALLBACK`과 Supabase의 허용 복귀 주소를 함께 변경해야 합니다. 기본 설정은 고정된 SCYL 웹 주소의 `/auth.html`, 설치형은 `/auth.html?target=native`입니다.

## 인증 흐름

이메일 입력 → 메일 발송 → 메일 승인 버튼 → 고정 웹 인증 화면 → 서버에서 회원 확인 → 음악 화면 순서입니다. PKCE를 사용하므로 메일을 요청한 브라우저 또는 앱에서 인증을 마칩니다. 다른 브라우저에서 요청한 링크를 임의로 채택하지 않습니다. URL의 인증 코드·과거 방식 토큰은 화면 이력에서 제거합니다. 메일에 숫자 인증 코드가 포함된 설정에서는 코드 입력도 지원합니다.

설치형 앱은 웹 인증 화면의 명시적인 **SCYL 앱으로 돌아가기** 링크로 `com.scyl.app://auth`를 열고, 앱 안에 저장된 요청 정보로 인증을 마칩니다. 웹 세션을 설치형 앱으로 복사하지 않습니다. 링크와 코드가 만료되면 새 메일을 요청합니다. 로그인·전경 복귀 자체가 음악을 자동 재생하지 않습니다.

SCYL 세션 저장 이름은 `scyl-auth-v1`이며 로그아웃은 현재 SCYL 세션 범위입니다. MEOW의 로그인 상태와 공통 회원 자체를 삭제하지 않습니다. 클라이언트 화면 잠금은 서버 데이터 권한 검증을 대체하지 않습니다. 향후 서버 저장 기능은 회원 ID에 대한 서버/RLS 권한 검사를 별도로 적용해야 합니다.

## 운영 검증 범위

2026-11-25 확인 시 기존 MEOW 기본 복귀 주소는 만료된 임시 터널이었습니다. SCYL은 명시적인 고정 복귀 주소를 요청에 전달합니다. 기존 MEOW 기본 주소와 일반 회원용 이메일 운영 설정은 별도 점검 대상입니다. 기본 메일에는 승인 링크만 있고, 맞춤 SMTP가 설정되지 않아 숫자 코드 본문 편집이 제한되어 있습니다. 테스트 수신자에게 메일이 도착했다는 사실은 모든 신규 회원에게 발송할 수 있다는 증거가 아닙니다.

Sites의 기존 웹 미리보기 로그인 및 소유자 접근 제한은 그대로 유지됩니다. MEOW 공통 회원 인증과 호스팅 접근 권한은 별개이며, 공통 계정 추가만으로 다른 회원에게 미리보기 사이트가 공개되지는 않습니다. 앱스토어 배포, 실제 iPhone/Android의 승인 링크 복귀, 일반 가입자의 메일 수신은 각각 별도로 확인해야 합니다.
