# MEOW · SCYL 공통 계정

SCYL은 같은 Supabase Auth 프로젝트를 연결해 MEOW의 기존 회원 ID를 재사용합니다. 별도의 회원 복사나 이메일 문자열을 이용한 임의 계정 병합을 하지 않습니다. 음악 파일·분석·재생목록을 MEOW 서버로 전송하지 않습니다.

## 설정과 실행

`.env.example`을 로컬 `.env.local`로 복사한 뒤 같은 프로젝트의 `SCYL_SUPABASE_URL`과 공개용 `SCYL_SUPABASE_ANON_KEY`만 설정합니다. 관리자 `service_role` 또는 secret 키는 허용하지 않습니다. 설정은 브라우저용 공개 클라이언트 값으로 번들에 포함됩니다. `npm start`는 빌드한 웹 앱을 실행하고, `npm run native:sync`는 같은 인증 코드를 두 설치형 앱에 포함합니다. 설정이 없는 로컬 빌드는 계정 연결 없이 실행됩니다. 배포용 빌드의 설정 누락은 별도로 점검해야 합니다.

공식 저장소의 네이티브 빌드는 같은 이름의 GitHub 저장소 변수를 사용합니다. 다른 운영 서버로 배포할 때 `lib/account-links.mjs`의 `ACCOUNT_CALLBACK`과 Supabase의 허용 복귀 주소를 함께 변경해야 합니다. 기본 설정은 고정된 SCYL 웹 주소의 `/auth.html`, 설치형은 `/auth.html?target=native`입니다.

## 인증 흐름

이메일 입력 → 메일 발송 → 메일 승인 버튼 → 고정 웹 인증 화면 → 서버에서 회원 확인 → 고양이·MBTI 선택 → 음악 화면 순서입니다. 이미 선택을 저장한 회원은 선택 화면을 건너뜁니다. 웹은 Supabase의 브라우저용 이메일 링크 방식을 사용합니다. 메일을 다른 브라우저에서 열어도 서버에서 검증한 이메일을 확인하고 **음악 듣기**를 누르면 그 브라우저에 로그인됩니다. 인증 토큰은 즉시 주소에서 지우고 메모리에서만 처리하며, 사용자 확인과 서버 검증 전에는 세션을 저장하지 않습니다. 다른 계정으로 로그인한 세션을 자동으로 덮어쓰지 않습니다.

설치형 앱은 PKCE를 유지합니다. 이전 웹 버전에서 발송한 PKCE 메일도 지원하지만, 해당 메일은 요청했던 브라우저의 인증 정보가 있어야 사용할 수 있습니다. 만료·사용 완료·인증 정보 누락은 별도 결과 화면에 표시하며 이메일 입력 화면으로 자동으로 되돌리지 않습니다. 메일에 숫자 인증 코드가 포함된 설정에서는 코드 입력도 지원합니다.

설치형 앱은 웹 인증 화면의 명시적인 **SCYL 앱으로 돌아가기** 링크로 `com.scyl.app://auth`를 열고, 앱 안에 저장된 요청 정보로 인증을 마칩니다. 웹 세션을 설치형 앱으로 복사하지 않습니다. 링크와 코드가 만료되면 새 메일을 요청합니다. 로그인·전경 복귀 자체가 음악을 자동 재생하지 않습니다.

SCYL 세션 저장 이름은 `scyl-auth-v1`이며 로그아웃은 현재 SCYL 세션 범위입니다. MEOW의 로그인 상태와 공통 회원 자체를 삭제하지 않습니다. 클라이언트 화면 잠금은 서버 데이터 권한 검증을 대체하지 않습니다. 향후 서버 저장 기능은 회원 ID에 대한 서버/RLS 권한 검사를 별도로 적용해야 합니다.

0.4.4부터 이 기기에서 마지막으로 로그인에 성공한 이메일을 `scyl.last-email.v1`에 기억합니다. 다음 로그인 화면의 빈 입력칸에 채우며 사용자가 직접 입력하거나 지운 값은 덮어쓰지 않습니다. 로그아웃해도 이메일만 남고, 개인정보 안내의 기기 데이터 삭제로 지울 수 있습니다. 저장한 이메일은 인증이나 회원 권한의 근거로 사용하지 않습니다. 인증 성공 화면은 **음악 듣기**만 제공하며, 로그인을 완료하기 전에 플레이어로 이동시키던 중복 링크는 제거했습니다.

0.4.2부터 이미 열린 인증 페이지로 승인 결과가 도착하는 경우도 처리합니다. 주소 변경·뒤로 가기·페이지 복원 시 현재 주소를 한 번만 읽어 인증 화면을 교체하며, 이전 요청의 늦은 응답은 새 화면을 변경하지 않습니다. 실제 계정 승인 전에는 인증 토큰을 저장하지 않습니다.

## 운영 검증 범위

2026-11-25에 맞춤 SMTP를 연결하고 프로젝트의 이메일 발송 한도를 시간당 2통에서 30통으로 변경한 뒤 저장 상태를 확인했습니다. 앱의 60초 재요청 간격은 중복 클릭 방지이며 서버 발송 한도와 별개입니다. 현재 메일 본문은 승인 링크 방식입니다. SCYL은 고정 복귀 주소를 명시하며, 0.4.3에서 Supabase가 정상 승인 링크에 포함하는 빈 `sb=` 항목을 처리하도록 수정했습니다. 실제 메일로 데스크톱 로그인과 새로고침 후 로그인 유지를 확인했습니다. 이 검증은 모든 기기와 신규 회원의 발송·로그인을 검증했다는 의미는 아닙니다. 기존 MEOW의 기본 복귀 주소와 운영 배포는 별도 점검 대상입니다.

사용자 요청에 따라 웹 주소의 ChatGPT 로그인 단계는 제거했습니다. 주소를 열면 SCYL에 직접 접근하며, 음악을 이용할 때의 MEOW · SCYL 공통 회원 인증은 유지합니다. 앱스토어 배포, 실제 iPhone/Android의 승인 링크 복귀, 일반 가입자의 메일 수신은 각각 별도로 확인해야 합니다.

## 공통 고양이·MBTI 정보 (0.4.5)

MEOW와 SCYL은 같은 Auth 회원 UUID에 연결된 account_private.member_profiles 한곳을 원본으로 사용합니다. get_shared_profile은 본인의 확정 정보를 읽고, save_shared_profile은 최초 선택을 확정합니다. 이미 MEOW에 확정된 고양이·MBTI를 우선 보존하며, 미확정 회원은 어느 앱에서든 같은 선택 화면으로 최초 확정합니다. 기존 MEOW의 확정 후 변경 제한을 유지합니다.

SCYL의 별도 user_metadata.scyl_profile_v1 읽기·쓰기는 제거했습니다. 이 값이 이미 있던 회원은 기존 MEOW 정보가 없는 경우에만 migration 0030이 한 번 가져옵니다. 이후 두 앱은 공통 RPC만 사용하며 브라우저 저장값은 인증과 프로필 원본의 근거가 아닙니다. 프로필 조회 실패는 재가입 화면이나 새 선택으로 보내지 않고 재조회합니다.

공통 프로필을 저장해도 MEOW 공개 고양이·위치·동네 공개·에너지 기록은 생성하지 않습니다. 기존 MEOW의 공개 등록 흐름은 공통 확정값과 일치하는지 서버에서 검증합니다. MEOW 고유 탈퇴와 공통 계정 삭제는 별도 운영 범위입니다.

고양이 120종과 MBTI 16종 선택 화면은 유지합니다. 원본 그림의 출처는 assets/companions/PROVENANCE.md에 기록했습니다. 운영 SQL 적용과 각 앱 배포 상태는 별도의 릴리스 기록으로 확인합니다.

서버 변경 원본은 `supabase/migrations/0030_shared_companion_profile.sql`입니다. 기존 MEOW 스키마와 0001–0028 마이그레이션 위에 적용하며, 빈 Supabase 프로젝트용 독립 초기화 스크립트는 아닙니다. 0029의 MEOW 가입·탈퇴 변경과는 독립적으로 검증합니다. 2026-11-25 운영 적용 때 기존 MEOW 회원·고양이·위치 공개·동의 기록의 전체 행 해시가 변경되지 않았고, 공통 프로필과 기존 확정값의 불일치가 0건임을 확인했습니다. MEOW 프론트엔드의 운영 배포 연결은 별도 확인 대상으로 남습니다.
